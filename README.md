# Miracle Markdown

一个用 TeX 的方式排版 Markdown 的编辑器。macOS 与 Windows，Tauri 2 + Rust。

浏览器的断行是贪心的：逐行填字，填不下就换行，从不回头。这里不是。整段文字交给
Knuth–Plass 优化器，为每个合法断点计算代价，用动态规划找出总代价最小的一组断点。
中文排版的三条规则——中西文间距、标点挤压、避头尾——不是特例，它们由同样的
box / glue / penalty 三种原语表达出来。

## 它现在能做什么

- **Knuth–Plass 整段最优断行**，TeX 的三趟策略：先尝试紧凑且不连字，失败后放宽并
  允许连字，最后一趟带 emergency stretch 保证一定有解。
- **中西文间距**：汉字与拉丁字母之间 ¼ em，可压缩到 ⅛ em。建模为 glue，因此在断行
  处会自动消失——这正是所需的行为。
- **标点挤压**：全角标点让出空着的半个字身。左对齐类（。，、：；！？和闭括号）右侧可缩，
  右对齐类（（「《【）左侧可缩，居中类两侧各缩 ¼ em。支持 GB / JIS / CNS 三种风格。
- **避头尾**：禁止的断点就是一个无穷大的 penalty，优化器自动绕开。
- **标点悬挂与字符突出**：行尾标点探出版心，右边缘因此笔直。西文的句点、逗号、连字符
  按 pdfTeX 的 `\rpcode` 约定突出。
- **西文连字**：Liang 算法 + TeX 断词模式（hypher）。连字点在**分词阶段**产生，
  因此每个音节都由宿主真实测量；未被断开的词在绘制前重新合并成一次 `fillText`，
  词内字偶间距不丢。
- **字体伸缩**：pdfTeX 的 `hz`，字形横向缩放 ±2% 以减轻词距负担（默认关闭）。
- **可编辑**：光标、选区、拖选、撤销重做、剪贴板，以及**中文输入法**（组合中的拼音在
  文档里就地显示并实时排版）。
- **劣度视图**：把每行的拉伸量显色，暖色偏松，冷色偏紧。
- **数学公式**：MathJax 排版、我们绘制。行内 `$…$`、`\( \)`，行间 `$$…$$`、`\[ \]`、
  以及信息串为 `math` 的围栏块。公式作为一个带宽度、**高度与深度**的盒子进入水平表，
  所在行会自动让出空间。支持公式编号、physics / mhchem / braket / mathtools 宏包，
  以及严格与宽松两套分隔符规则。

## 架构

```
crates/typeset-core/     纯算法，无 I/O，27 项测试
  unicode.rs             汉字与标点分类、避头尾表（CLReq / JLReq）
  prepare.rs             文本 → box/glue/penalty 水平表
  linebreak.rs           Knuth–Plass 优化器（三趟、活动集剪枝、适配度分级）
  layout.rs              断点 → 字形坐标（伸缩分配、标点位移、悬挂、字体伸缩）

crates/typeset-wasm/     wasm-bindgen 桥，每段两次调用，平坦 TypedArray
src/                     前端：测量缓存、Markdown 解析、Canvas 渲染、编辑器
  engine/math.ts         SVG → Path2D：变换代数与几何提取
  engine/mathjax.ts      MathJax 桥：懒加载、同步渲染、按公式缓存
  ui/math-panel.ts       公式设置面板
src-tauri/               桌面外壳：窗口、菜单、文件读写
```

**关键取舍：位置归我们，光栅化归平台。** 引擎算出每个字形该在哪里，绘制交给
Canvas2D `fillText`。排版质量全部在位置里，清晰度全部在光栅化里——自己写光栅器会
得到偏灰的字，Windows 用户期待的 ClearType 就没了。

拉丁词整词一次 `fillText`（保住词内 kerning 与连字，反正词是断行器眼中不可分的 box），
汉字逐字绘制（才能做挤压和悬挂）。

**测量在 JS 侧，断行在 Rust 侧。** `measureText` 用的是平台稍后绘制时的同一个整形器，
所以优化器推理的宽度就是最终出现的宽度。测量结果按 token 缓存，一整段的重新测量
约 2 µs。

引擎依赖的核心不变量：**每个盒子的宽度必须等于它所绘制文本的实测宽度**。违反它，
相邻的绘制单元就会重叠或裂开，因为下一个单元的位置就是靠累加这个宽度得到的。一个
被拆开的词若只按字符数均摊宽度，`i` 和 `m` 就被当成一样宽——这正是连字功能最初
出错的原因。

**行不排在固定网格上。** 每行有自己的高度与深度，基线由 TeX 的行间胶水算出：目标是
恒定的基线间距，但当某一行装了比正文高的东西、按目标排会碰撞时，就改用 `lineskip` 的
最小间隙。正文行高度处处相同时，这套算术精确退化为等距——所以普通段落不会因此起伏，
而夹着公式的那一行会自动让开。

**版面几何只取决于窗口与"版心"设定，与字号无关。** 用 em 来定行长在排版上更有道理
（行长本该以字符数衡量），但那会让边距随字号滑动，读起来像页面在散架而不是字在变大。
行长因此有了自己的控件。

## 实测数据

在 M 系列 Mac、1280×800 窗口、1360 字符的混排文档上：

| 项目 | 数值 |
|---|---|
| 全文重排（21 块 / 38 行） | **1.6 – 3.0 ms** |
| KP 断行，500 字段落 | 0.38 ms |
| 整段测量（无缓存 → 有缓存） | 86 µs → **2 µs** |
| 逐字 Canvas 渲染，45 行 × 40 字 | **0.57 ms/帧** |
| 对比：DOM `Range` 逐字测量 | ~15.7 µs/字（**慢约 290 倍**） |

最后一行是这套架构的由来：任何"用 DOM 量文字、用 CSS 排版"的路线都扛不住每次击键。

**Knuth–Plass 对比贪心**（18 em 窄栏英文）：

| | 行数 | 最差 \|r\| | 总劣度 |
|---|---|---|---|
| 贪心（浏览器的做法） | 6 | 2.00 | 2239 |
| Knuth–Plass | 6 | 0.45 | **27** |

**跨引擎一致性**：同一份文档在 WKWebView（macOS Tauri 的渲染器）与 Chromium 中
断点完全相同 —— `[23, 65, 105, 143]`，调整比 `[0, 0.0025, −0.4, 0.0005]`，逐位一致。
注意这是同机同字体的结论；Windows 的系统字体不同，因此正式版应自带字体。

npm run tauri dev # 桌面应用

只跑前端（浏览器里预览，文件操作退化为下载/上传）：

```bash

```

```bash
npm test          # 全部：27 项 Rust + 四组 TypeScript
```

分别是：`typeset-core`（算法与排版规则）、`parse`（Markdown 解析）、`coalesce`
（绘制单元合并）、`math-parse`（公式分隔符规则）、`math-transform`（SVG 变换代数）。

## 公式

排版交给 MathJax，绘制归我们。MathJax 输出 SVG，我们把其中的字形轮廓提取成一个
`Path2D`，用与正文相同的坐标系画在画布上——不进 DOM，不加载网页字体，一条公式一次
`fill`。

这个选择是被架构逼出来的：页面上每个字形的位置本来就由我们决定；若公式以 DOM 子树的
形式交付，就得叠在画布上并与我们自己的滚动和布局保持同步，而且导出 PDF 时会丢失。
轮廓画在画布上则与文字同处一个坐标空间，缩放不重采样。

公式需要的三个数——宽度、基线以上的高度、基线以下的深度——直接来自 SVG 自身的属性，
因此它作为一个普通的盒子进入水平表。行内公式在渲染文本里由 **U+FFFC**（对象替换符）
占位，这正是该码位的用途，也意味着分词器不需要为它设特例。

**已验证的不变量**：把公式按渲染器的方式画进离屏画布再扫描墨迹范围，墨迹始终落在分配的
盒子内（差值是字形边距），基线与分配的高度一致。这与文字遵守的是同一条规则。

### 选项为什么存在

每个选项都对应一处实现间的真实分歧，不是偏好：

| 选项 | 它实际改变什么 |
|---|---|
| 严格分隔符 | 沿用 Pandoc 规则：开分隔符后不能是空格，闭分隔符前不能是空格、**后不能是数字**。最后一条是让「$5 和 $10」保持为价格的原因。关闭后回到宽松匹配，用于读旧文档。 |
| TeX 分隔符 | `\( \)` `\[ \]` 与 Markdown 的反斜杠转义冲突，必须**先于**转义规则识别，否则公式会被逐字符吃掉。 |
| physics 宏包 | 实测：`a \div b` 在基础宏包下宽 4.933ex，载入 physics 后变成 6.062ex——它**重定义了 `\div`**（除号 → 散度算符）。这就是它必须 opt-in 的原因。 |
| 公式编号 | `none` / `ams` / `all`。`\tag{…}` 始终优先，`\notag` 始终抑制；`ams` 按 LaTeX 约定只给 equation、align、gather 等编号，带星号的形式不编号。 |

编号在文档布局那一趟里按顺序分配。放在解析器里的话，公式的编号将取决于它看不见的东西；
交给 MathJax 的话，则要在本可以各自独立缓存的渲染之间维持全局计数器。

## 编辑模型

文档的真值是 Markdown 源码。光标所在的块显示它的源码，其余块保持排版后的样子。
这绕开了"光标停在 `**` 中间该怎么办"这个本质上无解的问题，并且让最需要精确的地方
——光标所在处——的映射成为恒等。

其余块通过每个字形携带的源码字节区间映射回去，所以点击定位是一次二分查找。这是
编辑器与阅读器的分界线，也是整个数据结构里唯一不能省的簿记。

## 尚未完成

- **可断行的行内公式**。TeX 允许在行内公式的顶层二元运算符与关系符之后断行
  （`\binoppenalty = 700`、`\relpenalty = 500`）；目前公式是一个不可分的盒子。
  做法已经清楚：把公式在顶层拆成若干片段，片段之间放上对应惩罚，KP 会自己处理。
  这是几乎所有 Markdown 编辑器都没做的一件事。
- **`\label` / `\ref` 交叉引用**。编号已经有了，引用解析还没做。
- **无障碍**。Canvas 上的文字对屏幕阅读器不可见，需要隐藏 DOM 镜像或 AccessKit。
- **表格**。解析与排版都还没做。
- **Windows 实机验证**。代码是跨平台的，但输入法候选窗定位在 WebView2 上尚未实测。
- **视口虚拟化**。目前每次重排都处理整篇文档；1.6 ms 对中等长度文档足够，但打开
  10 MB 文件需要只排可见部分。
